# Self-Improvement Loop

## Purpose

Make the Brillect operating system sharper over time by learning from meetings, emails, relationship outcomes, opportunity movement, and Seth's edits.

## Default Operating Loop

1. Before meetings, use Briefer to prepare around relationship path, buyer type, likely trigger, and possible assessment bridge.
2. After meetings, Seth provides a raw brain dump or notes.
3. The system extracts signal, asks targeted follow-up questions, and produces operating artifacts.
4. The system updates durable memory and relevant Brillect data files when Seth approves or requests updates.
5. Weekly, use Weekly Scorecard to review what created real pipeline rather than just activity.
6. Monthly, improve qualification rules, outreach style, assessment language, priority relationship categories, and trigger patterns.

## Post-Meeting Output Standard

After a meeting debrief, produce:

1. Bullhorn note draft
2. Follow-up draft or drafts
3. Suggested memory updates
4. Suggested updates to consistent Brillect files
5. Opportunity rating: A, B, C, or Nurture
6. One system learning, if there is a useful pattern to preserve

## Bullhorn Note Format

Use a polished, neutral, transferable style. The note should be easy for someone else at Brillect to review later.

```text
Meeting/Call:
Contact(s):
Company:
Date:
Relationship Context:
Discussion Summary:
Business Triggers / Pain Points:
Potential Brillect Fit:
Qualification:
- Urgency:
- Budget:
- Decision Path:
- Timing:
Next Step:
Follow-Up Needed:
Internal Notes:
```

If the meeting is early or nurture-oriented, be clear:

```text
Qualification:
Early relationship conversation. No confirmed active project yet. Need to test urgency, budget, and executive priority in next touch.
```

## Durable Learning Categories

When new information is learned, classify it as one or more of:

- Relationship learning: who trusts Seth, who is influential, who can make introductions
- Trigger learning: which signals are creating real opportunity
- Buyer learning: what CHROs, CFOs, PE sponsors, and attorneys respond to
- Assessment learning: which assessment language feels natural and creates momentum
- Voice learning: phrases Seth likes, edits, or rejects
- Qualification learning: what turned out to be real pipeline versus noise
- Market learning: Milwaukee events, firms, companies, sponsors, or advisors that matter

## File Update Guidance

Use these files for durable updates:

- `data/followups.md`: pending relationship actions
- `data/pipeline-top.md`: active qualified opportunities
- `data/watchlist.md`: stalled or at-risk opportunities
- `data/channel-partners.md`: attorney and other channel relationships
- `data/signals.md`: market intelligence and trigger events
- `data/target-accounts.md`: priority accounts
- `system/seth-role.md`: Seth's role, priorities, and pipeline model
- `system/voice-and-tone.md`: outreach style and examples
- `system/pipeline-qualification.md`: qualification rules and ratings
- `system/self-improvement-loop.md`: how the operating system learns

## Improvement Rule

Every substantive debrief should try to preserve one useful learning, but only if it is real. Do not invent patterns from thin evidence.
